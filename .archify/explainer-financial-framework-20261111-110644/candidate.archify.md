# الإطار المالي والتدفقات النقدية لنظام الادخار {#financial-framework}

يعمل نظام الادخار كمنظومة مالية مترابطة تفصل بين **استحقاق العضو، والتحصيل النقدي، والقيد في الحساب، والاستثمار، والضمان، والصرف**. ويحافظ هذا الفصل على حقوق الأعضاء، ويكشف فجوات التحصيل والسيولة، ويمكّن من مطابقة الأرصدة مع النظام المالي.

- يسجل النظام كل مصدر مالي في وعاء مستقل، مع عرض رصيد موحد للعضو.
- يعتمد العائد على الحسابات الشهرية في نموذج V3، مع حساب موازٍ لضمان 2%.
- تطبق التسوية الشهرية وفق التسلسل التشغيلي الحالي، مع فصل الأصل عن الغرامات.
- تعاد حسابات الأجر والعوائد بأثر رجعي من أول شهر متأثر، دون حذف السجل السابق.

## ما هي الحسابات والاحتياطيات الحاكمة؟ {#accounts-reserves}

| الحساب | وظيفته | قاعدته المالية |
| --- | --- | --- |
| الحساب الفعلي | يعرض مساهمات وإيداعات وسحوبات العضو والعائد المعلن | يستخدم العائد السنوي الفعلي أو المعلن، دون فرض حد 2% سنوي داخله |
| حساب ضمان 2% | مسار موازٍ لنفس الحركات | ينمو بنسبة 2%، ويقارن بالحساب الفعلي عند بدء الصرف |
| حساب اشتراكات جهة العمل المضمونة `GECA` | يقيس ما كان سيصبح عليه الحساب لو سدد صاحب العمل كامل 9% | يستخدم الاشتراك المقرر والعائد الفعلي لمتابعة نقص السداد |
| احتياطي ضمان العائد | يمول الفرق بين حساب الضمان والحساب الفعلي | يستخدم عند اختبار الضمان في بداية الصرف |
| احتياطي تعثر جهة العمل | يغطي أثر الاشتراكات غير المسددة وفق الآلية المعتمدة | تغذيه الاستردادات اللاحقة من جهات العمل، ويظل منفصلًا عن احتياطي العائد |

## كيف يعاد احتساب الأجر والعائد بأثر رجعي؟ {#retro-recalculation}

@workflow id=retro-wage-flow title="محرك إعادة الاحتساب الرجعي"
| lane trigger | تثبيت التصحيح |
| lane rebuild | إعادة بناء الأشهر |
| lane result | تسجيل الفروقات |
| corrected-wage | أجر جديد مؤرخ | external | trigger |
| first-month | تحديد أول شهر متأثر | backend | trigger |
| contributions | إعادة احتساب 9% | backend | rebuild |
| balances | إعادة بناء الأرصدة الشهرية | database | rebuild |
| returns | إعادة احتساب العوائد | backend | rebuild |
| compare | مقارنة النتيجتين | security | result |
| adjustment | قيد فرق موجب أو سالب | database | result |
| corrected-wage > first-month | تاريخ السريان |
| first-month > contributions | شهرًا بشهر |
| contributions > balances | فروق الاشتراكات |
| balances > returns | من الشهر التالي |
| returns > compare | قديم مقابل مصحح |
| compare > adjustment | فرق نهائي | emphasis |

تعاد سلسلة الحساب من أول شهر متأثر حتى أحدث شهر مغلق. ويستبدل محرك الحساب الأجر القديم بالأجر المصحح داخل النسخة الجديدة، ثم يعيد احتساب الاشتراكات والأرصدة والعوائد والضمانات بالترتيب الزمني نفسه.

- الزيادة تنتج فرق اشتراك موجبًا وعائدًا إضافيًا متراكمًا.
- النقص ينتج فرق اشتراك سالبًا وعكسًا للعائد الزائد.
- لا تحذف النسخة السابقة؛ تحفظ النتيجة قبل التصحيح وبعده وسبب التعديل ومرجعه.
- تبقى التسوية النقدية مسارًا منفصلًا عن إعادة الاحتساب الرياضي.
- إذا سبق الصرف، يسجل الفرق كمبلغ مستحق أو واجب الاسترداد بدل تعديل عملية صرف مغلقة.

## كيف تصنف مصادر الأموال؟ {#fund-sources}

| المصدر | الوعاء | المعالجة الرئيسية |
| --- | --- | --- |
| اشتراك إلزامي 9% | إلزامي | فاتورة شهرية، تسوية، حساب فعلي، `GECA`، وضمان 2% |
| إيداع المدخر | اختياري ـ مدخر | حد أدنى وسقف سنوي مستقل، ويبدأ العائد من الشهر التالي |
| إيداع جهة العمل الاختياري | اختياري ـ جهة عمل | سقف مستقل لكل عامل، ولا يخصص قبل تأكيد السداد |
| تسوية نهاية الخدمة السابقة | تسوية ما قبل النظام | فاتورة مستقلة، ثم تخصيص مرجعي لكل عامل بعد السداد والمطابقة |
| فائض الاشتراكات | فائض مستقل | لا يدخل في السقف الاختياري، وله قواعد صرف وعائد خاصة |
| نصيب البرنامج التكميلي | إيداع مباشر مستقل | يحتسبه النظام المصدر، ويقيد بمرجع فريد وتاريخ قيمة |
| مبالغ حالات الجنسية | إيداع مباشر مستقل | يقيد صافي المبلغ الوارد من نظام الاشتراكات كمصدر مستقل |
| استرداد متأخرات جهة العمل | احتياطي التعثر | لا يعاد قيده للعضو إذا سبق تغطية النقص من الاحتياطي |

يحتفظ كل مصدر بمؤشرات مستقلة لأهلية العائد والضمان والصرف والسقف والحساب المحاسبي. ويعرض الحساب الإجمالي دون فقد هذا التفصيل.

## كيف يحتسب العائد وتنفذ الضمانات؟ {#returns-guarantees}

@workflow id=return-guarantee-flow title="العائد الفعلي وضمان 2%"
| lane accumulation | فترة الادخار |
| lane payout | بداية الصرف |
| actual | الحساب الفعلي | database | accumulation |
| declared | العائد المعلن | backend | accumulation |
| guaranteed | حساب 2% الموازي | security | accumulation |
| geca | حساب `GECA` | security | accumulation |
| test | اختبار الضمان | backend | payout |
| topup | تمويل الفرق | database | payout |
| payout | الحساب بعد بدء الصرف | backend | payout |
| declared > actual | معامل شهري | emphasis |
| actual > test | رصيد فعلي |
| guaranteed > test | رصيد مضمون |
| geca > topup | نقص السداد |
| test > topup | عند وجود فرق | security |
| topup > payout | رصيد البداية | emphasis |

المعامل الشهري للعائد هو `(1 + العائد السنوي)^(1/12) − 1`. يحتسب العائد على الرصيد الافتتاحي بعد خصم سحب الشهر، ثم تضاف مساهمات الشهر إلى الرصيد الختامي وتبدأ عوائدها في الشهر التالي.

عند بدء الصرف، يقارن الحساب الفعلي بحساب ضمان 2%. يمول احتياطي ضمان العائد الفرق إن كان الحساب المضمون أعلى. بعد التسوية يستمر الحساب الفعلي وحده خلال فترة الدفع، وفق عائد مرحلة الصرف المعتمد ودون ضمان جديد.

## كيف تنفذ عمليات الصرف؟ {#disbursement}

| الحالة | نطاق الصرف | معاملة العائد |
| --- | --- | --- |
| الاستحقاق العام | كامل الرصيد المستحق بعد تسوية الالتزامات | تنفذ مقارنة الضمان قبل بدء الصرف |
| الأقساط | طريقة دفع لكامل استحقاق معتمد، وليست سحبًا جزئيًا اختياريًا | يستمر العائد على الرصيد المتبقي بعد تسوية الضمان |
| غير العماني | بعد انتهاء العمل والمغادرة، أو بعد ثلاثة أشهر دون عقد جديد | تكتمل التسوية الإلزامية قبل الدفع |
| فائض الاشتراكات | فائض العام المنصرم فقط، دون باقي الرصيد | يصرف بسبب الفائض دون عائد؛ ويخضع للعائد عند الاستحقاق العام |
| الخروج المتأخر | الرصيد المستحق وفق شروط الخروج | 2% لسنة واحدة ثم يتوقف العائد وفق القاعدة الحالية |
| الوفاة | صافي الرصيد للورثة الشرعيين | يتوقف العائد في تاريخ الوفاة |
| التحويل الدولي | صافي الاستحقاق بعد الرسوم وفروق العملة | يبقى الطلب مفتوحًا حتى نجاح التحويل، وتوثق كل محاولة مستقلة |

تنتقل عملية الصرف من حساب العضو إلى حساب مستحقات الصرف عند اعتمادها ماليًا. يرسل النظام المعاملة إلى Oracle، ويستقبل مرجع التنفيذ أو الارتداد. ولا يغلق الطلب حتى يصل المبلغ إلى المستفيد.
